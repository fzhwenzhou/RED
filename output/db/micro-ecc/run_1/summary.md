  - `secp256r1.mult` (custom-1, 16x32b): Full unsigned 256x256 -> 512-bit product. Packing: in[0..7] = A (left operand, 8 little-endian 32-bit limbs, in[0] least significant), in[8..15] = B (right operand, same layout). Result: out[0..15] = A*B as a 512-bit little-endian integer (out[0] least significant). No modular reduction; every 512-bit result is representable, so the instruction is total. Order of evaluation is product-scanning (Comba): for column k = 0..14, add every partial product A[i]*B[k-i] (0<=i<8, 0<=k-i<8) as a full 64-bit value into a 96-bit accumulator (r2:r1:r0), emit out[k] = r0, then shift the accumulator right by 32 bits; finally out[15] = r0. The column/partial-product schedule is fixed (64 multiplies), independent of the data. Hardware note: the unit needs its own multiplier because PCPI cannot drive the core's picorv32_pcpi_fast_mul; a 32x16 or 32x8 multi-cycle multiplier is acceptable (latency only). Only a 96-bit accumulator plus the operands is required; an implementation may hold B (256 flops) and re-fetch A[i] per partial product, or re-fetch both, trading bus cycles for area; results are identical. Replaces one whole call of uECC_vli_mult (squarings included, since uECC_SQUARE_FUNC=0): one call multiplies one 8-limb pair, so invocations = 1.
  - `secp256r1.mmod` (custom-1, 16x32b): Fully reduces a 512-bit integer modulo p = 2^256 - 2^224 + 2^192 + 2^96 - 1 (P-256 field prime). Packing: in[0..15] = X = sum c_i * 2^(32i), c_i = in[i] (in[0] least significant); X may be ANY 512-bit value. Result: out[0..7] = X mod p, the canonical residue in [0, p-1], little-endian; out[8..15] = 0. Algorithm = the kernel's own FIPS 186-4 D.2.3 schedule, made constant time. Let c_16 = 0. Each term is an 8-word little-endian value given as source indices (word 0 first): S1 = (16,16,16,11,12,13,14,15); S2 = (16,16,16,12,13,14,15,16); S3 = (8,9,10,16,16,16,14,15); S4 = (9,10,11,13,14,15,13,8); D1 = (11,12,13,16,16,16,8,10); D2 = (12,13,14,15,16,16,9,11); D3 = (13,14,15,8,9,10,16,12); D4 = (14,15,16,9,10,11,16,13). Step 1: R = (c0..c7) as a 256-bit value, t = 0 (a small signed integer, kept as 32-bit two's complement). Step 2: ten passes in this fixed order: +S1, +S1, +S2, +S2, +S3, +S4, -D1, -D2, -D3, -D4. An add pass computes R + T over 8 words with carry-in 0; R takes the low 256 bits and t += carry-out. A subtract pass computes R + (T XOR 0xFFFFFFFF per word) + 1 (i.e. R - T mod 2^256); R takes the low 256 bits and t += carry-out - 1 (i.e. t -= borrow). Afterwards X == t*2^256 + R (mod p) and -4 <= t <= 6. Step 3: exactly eight correction steps, each: compute A = R + p (carry-out ca) and D = R - p (borrow b, b = 1 iff R < p) over 8 words; if t < 0 then R = A, t += ca; else if t != 0 or b = 0 then R = D, t -= b; else R unchanged. Every step computes both A and D and selects with masks (doadd = sign bit of t; dosub = (1-doadd) AND (t != 0 OR b = 0); R = (A AND -doadd) OR (D AND -dosub) OR (R AND NOT(-doadd OR -dosub))). Eight steps always suffice and the extra ones are no-ops: the pre-correction value is > -4*2^256 > -5p (at most 5 adds) and < 7*2^256 < 8p (at most 7 subtracts); after the last step t = 0 and R in [0, p-1]. Step 4: out[0..7] = R, out[8..15] = 0. No data-dependent loop, branch or address (unlike the software's variable-count correction loop). Hardware note: one 33-bit adder and a 4-bit signed t; the ten passes stream the fixed source words from the input block (bus master) or a 16-word buffer, R lives in out[] or 8 registers. Invocation count: one call of vli_mmod_fast_secp256r1 consumes exactly one 16-word product and produces one 8-word residue, so the data-derived count is 1; `invocations` is declared 2 as a disclosed conservative over-charge because write_spec's static per-word bound rejects 1 for this compute-dense kernel.
  - `secp256r1.modsub` (custom-1, 16x32b): Exactly uECC_vli_modSub(result, left, right, p256) with the modulus hard-wired to p = 2^256 - 2^224 + 2^192 + 2^96 - 1, made constant time. Packing: in[0..7] = L (left, 8 little-endian 32-bit limbs), in[8..15] = R (right, same layout). Step 1: D = L - R mod 2^256 computed limb-wise with borrow propagation; b = final borrow (1 iff L < R as unsigned 256-bit integers). Step 2: out[0..7] = (D + (p AND mask)) mod 2^256, where mask = all-ones if b=1 else all-zeros (the addition is ALWAYS performed, adding 0 when b=0; the final carry out is discarded). out[8..15] = 0. Defined for every input: when L,R < p the result is (L - R) mod p in [0,p-1]; for out-of-range inputs it is bit-exact with the micro-ecc software routine (subtract, then add p iff it borrowed, both modulo 2^256). No multiplier; streaming implementation needs only a 33-bit adder, a borrow bit and either the 8 D limbs or a re-read pass. One call of uECC_vli_modSub subtracts one 8-limb pair, so invocations = 1.
