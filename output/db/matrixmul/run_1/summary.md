- ISASpec: MatrixMul Float GEMM Extension (1 instructions)
  - `fgemm10.s` (custom-0, 200x32b): Operand block ABI: rs1 holds the word-aligned address of a 200-word input block in[0..199]. rs2 holds the word-aligned address of a 200-word output block out[0..199]. The two blocks must not overlap. Every word is an IEEE-754 binary32 bit pattern. Packing: in[0..99] is matrix A, 10x10 row-major, so A[i][k] = in[10*i + k] for i,k in 0..9. in[100..199] is matrix B, 10x10 row-major, so B[k][j] = in[100 + 10*k + j]. This is exactly the layout of Matrix.elements[] in the application for a 10x10 matrix, so the caller copies A->elements[0..99] and then B->elements[0..99] into one contiguous block. Computation: for each i in 0..9 and j in 0..9 (any order, since the elements are independent), acc_0 = +0.0 (bit pattern 0x00000000), then for k = 0,1,...,9 strictly in that order: p_k = A[i][k] * B[k][j] and acc_{k+1} = acc_k + p_k. Each multiply and each add is a separate IEEE-754 binary32 operation, rounded to nearest with ties to even. Nothing is fused and there is no wider intermediate precision. This is the order and rounding of the application's loop (clearMatrix stores +0.0, then C[i][j] = C[i][j] + A[i][k]*B[k][j] for k ascending), so the result is bit-identical. Subnormals are fully supported as inputs, intermediates and results: no flush-to-zero and no denormals-are-zero. NaN: if acc_10 for an element is any NaN (exponent all ones and fraction nonzero), that element's result is the canonical quiet NaN 0x7FC00000. Otherwise it is acc_10's exact bit pattern, including signed zero and the infinities. So inf*0 or (+inf)+(-inf) anywhere in the element's chain yields 0x7FC00000, and a NaN input in the chain also yields 0x7FC00000. Rounding mode is fixed at RNE. No fcsr is read or written (the core has no F extension), and all FP exception flags are discarded. Outputs: out[10*i + j] = C[i][j] for i,j in 0..9. out[100] through out[199] are each written with 0x00000000. rd receives out[0] (C[0][0]) with pcpi_wr=1. If rd = x0 the write is dropped as usual. Use and fallback: the caller (multiply()) uses the instruction only when A is 10x10, B is 10x10 and C does not alias A or B. Otherwise it runs the original software loop. On the fast path it sets C's rows and columns to 10, issues FGEMM10.S and copies out[0..99] into C->elements[0..99]. Hardware: a single binary32 multiply-add datapath (a 24x24 significand multiplier plus align/add/normalize/round, which is not a duplicate of the 32x32 integer fast_mul and is unreachable from PCPI anyway). It fetches operands through the harness bus-master path: per element it reads A row i (10 words) and B column j (10 words, stride 40 bytes) and runs 10 multiply-adds, keeping only the accumulator plus one operand pair as state (no 200-word buffer). A row-buffer variant (10 words of A cached per i) is an allowed implementation and gives identical results. Every multiply-add takes the same number of cycles with no early exit on zero, subnormal, infinity or NaN, and the loop trip counts are fixed (10x10x10), so latency is independent of operand values. pcpi_wait is raised the cycle after pcpi_valid (within the 16-cycle timeout). pcpi_ready is pulsed for one cycle, and the unit waits for !pcpi_valid (S_WAIT) before accepting another instruction.
