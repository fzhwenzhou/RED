- ISASpec: CRC32_Accel (1 instructions)
  - `crc32.step64b` (custom-1, 17x32b): Memory-operand instruction using the RED block ABI `crc32.step64b rd, rs1, rs2`. rs1 holds the byte address of a 17-word input block in[0..16]; rs2 holds the byte address of a 17-word output block out[0..16]; rd receives 0 (if rd is x0 nothing is written). Both addresses are word aligned: bits [1:0] of rs1 and rs2 are ignored (treated as 0). Input packing: in[0] is the running CRC-32 state exactly as held by the crc_32 loop variable `crc` (the caller applies the 0xFFFFFFFF start value and the final 0xFFFFFFFF XOR itself; the instruction applies neither). in[1..16] hold 64 data bytes in stream order, packed little-endian, so data byte k (k = 0..63) is (in[1 + floor(k/4)] >> (8*(k mod 4))) & 0xFF. This is byte-identical to the RV32 memory image of the data, so the caller copies 64 contiguous bytes of its buffer to in[1..16] unchanged. Operation: for k = 0..63 in order, crc = crc XOR byte_k, then 8 times crc = (crc >> 1) XOR (0xEDB88320 if bit 0 of crc was 1, else 0). This equals 64 iterations of crc = (crc >> 8) ^ crc_tab32[(crc ^ byte) & 0xFF]. Output: out[0] = the final crc; out[1..16] are all written with 0. The unit reads all 17 input words before writing any output word, so overlapping or identical in/out blocks are well defined. The latency is fixed (17 word reads, 17 word writes, and constant compute) and does not depend on operand values. Every 32-bit input is valid and the instruction raises no exceptions of its own.
