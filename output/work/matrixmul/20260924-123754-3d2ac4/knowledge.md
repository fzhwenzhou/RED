
For matrixmul on PicoRV32 with floats: dual FP MACs are rejected due to strict area constraints, so use a single multi-cycle sequential FP MAC. The canonical NaN for RISC-V is 0x7FC00000 and must be applied explicitly after every intermediate float operation (e.g., both multiplication and addition in a MAC). Since the instruction targets an inner statement, `invocations` should reflect the exact innermost loop trip count per function call (191 in this profile), and the prose must explicitly acknowledge it as an inner loop accelerator that relies on the host for outer loops.

Rewrote `canon_nan` to be strictly constant-time by avoiding branching on operand data values. Replaced the `if (exp == 0xFF && frac != 0)` condition with masked logic: `uint32_t is_nan = (exp == 0xFF) & (frac != 0); uint32_t m = (uint32_t)0 - is_nan; return (0x7FC00000 & m) | (bits & ~m);`. This fixes timing side-channel failures in CT-grind.

To make Spike models strictly constant-time and avoid `timing.data_dependent` or `timing.secret_branch` errors under Valgrind/ctgrind, completely avoid boolean operators (`==`, `!=`, `&&`, `||`) because compilers often lower them into conditional branches or jumps that Valgrind flags. Instead, implement constant-time bitwise masks (e.g., `uint32_t sign = (x | (0u - x)) >> 31;` followed by `0u - sign` to produce an all-1s mask when `x` is non-zero).
